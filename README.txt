项目名称：Minimal Coding Agent
Git 仓库：https://github.com/happy-299/CodingAgent

项目简介

Minimal Coding Agent 是一个简单但功能完整的编程智能体。项目使用 Python 标准库直连 DeepSeek 原生 tool calling，由模型在真实工作区中完成探索、规划、编码、测试与结果确认。

如何运行

在 .env 中配置 OPENAI_API_KEY，然后启动：

python3 coding_agent.py

指定目标项目：

python3 coding_agent.py --workspace /path/to/project

核心设计

1. Terminal-first：最简洁而通用的工具

随着大模型的代码与 Shell 能力增强，ls、rg、sed、构建器、测试框架和版本控制工具已经能够通过命令行自然组合。项目因此使用 terminal(command, timeout) 作为统一执行工具，让模型通过一个接口完成目录探索、文件读写、代码检索、程序运行、测试验证和差异检查。较少的工具描述降低了选择成本，命令行的可组合性则保留了完整能力。

除 terminal 外，项目提供 update_plan 状态工具。它不执行外部操作，只保存结构化待办项及其状态，使计划成为可持续更新的工作记忆，而不是一次性的文本说明。

2. 由模型自主决定是否规划

规划不是固定的第一步。模型会根据任务范围、未知信息和执行复杂度自行判断：简单任务可以直接完成；复杂任务则调用 update_plan 拆解目标、维护当前步骤，并随着新证据持续调整。Agent 提供规划能力，但不以形式化流程限制模型判断。

3. 先探索理解，再采取行动

Agent 鼓励模型先进行最小但充分的环境侦察：理解目录结构、现有实现、行为约定、测试入口和约束，再决定修改范围。每次 terminal 结果都会作为新的观察反馈给模型，形成“探索—行动—观察—调整”的闭环，减少建立在错误假设上的修改。

4. TDD 驱动的工程闭环

在开发任务中，Agent 以可验证行为为中心组织工作：先从需求和既有测试提炼验收标准，编写或复用能够暴露问题的测试，再完成最小实现；随后运行针对性测试、检查失败证据、迭代修复，并在结束前执行覆盖相关行为的回归测试。测试不仅用于最终确认，也持续指导设计和实现。

5. 完整的 Agent 能力

- 规划与执行：可选的结构化计划与通用 terminal 执行协同工作。
- 观察与恢复：terminal 返回退出码、输出大小、截断和超时等结构化信息，失败结果会进入下一轮决策。
- 上下文管理：保留多轮对话、推理、工具调用及结果，并按完整协议单元压缩历史；工作记忆持续保存任务、计划和关键证据。
- 终止判断：模型基于验收标准和实际证据判断任务是否完成，Agent 在结束前进行完成审计，并以轮次限制作为安全边界。
- 流式交互：推理、回答、计划和工具执行过程实时呈现，支持 Markdown、语义配色、固定计划和历史滚动。
- 可靠执行：支持 API 重试、命令超时、进程组清理、长输出截断、敏感环境变量过滤和工具协议恢复。
